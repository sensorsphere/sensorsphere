# NET-UI-04-FIX-01 — Persistent selection and simulator-style cards

## Root cause
NetatmoHeatingPanel stored the selected connection in local component state, which reset when navigating away. The sidebar and Dashboard Overview additionally cleared the requested target, causing fallback to the first connection (SIM-01).

## Fix
- The Dashboard owns the selected connection using the existing usePersistentState helper (`netatmo.heating.selectedConnection`), backed by browser localStorage.
- NetatmoHeatingPanel receives both the current connection ID and a selection callback; its tabs update the persisted state.
- Generic menu/Dashboard entry no longer clears the connection. Contextual links from Assets, Device Registry and History explicitly select their connection and update the persisted state.
- F5 restores the last selected connection. If that connection is deleted or missing, a warning is shown instead of silently selecting SIM-01.

## Telemetry cards
- Four tiles inspired by the simulator, in the same order: Indoor temperature (cyan), Setpoint temperature (amber), Outdoor temperature (purple), Boiler status (green).
- On wide screens tiles appear in one row; responsive layouts use two columns or one column.
- SensorSphere currently collects neither outside temperature nor independently verified boiler state: the corresponding tiles display `—` and `UNKNOWN`, never invented data. Thermostat heating demand is shown as explanatory text, not as verified boiler status.
- The thermostat card now uses the full row, with relay details below, to give the four tiles adequate width.

## Safety and scope
- Frontend-only; API unchanged; no simulator or physical heating command.
- DEV only, no TEST1 changes, no push.
