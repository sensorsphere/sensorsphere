# NET-UI-08 — Heating UI polish and query scoping

## Why unrelated GET requests appeared
The main `App` mounts TanStack Query observers for Sensors, Assets, Locations, Dashboards, Metric Display Settings, Classification, Gateways, Observations and Active Alerts independently of the active page. Those observers poll every 30 or 60 seconds even while Netatmo Heating is selected. The global app shell also checks authentication, module versions, frontend build-date and enabled project tasks. A browser Network screenshot alone does not prove which component initiated every GET.

## Scoped fix
- Disable nine unrelated domain queries while `activePage === 'netatmo-heating'`, retaining their cached data. Re-enable automatically when navigating back to the general pages.
- Retain authentication, module-version and frontend-build checks, which are app-wide safety/compatibility functions. Some requests may still occur in flight at the moment of navigation; browser cache and external background panels may also trigger requests.
- Netatmo Heating keeps its own 30-second `/api/v1/integrations/netatmo/connections/heating/overview` refresh and selected-connection command journal.

## Presentation
- Current mode is a colored Mantine badge (Schedule blue, Manual orange, Away violet, Frost protection cyan).
- Boiler icon is a vector burner, not an emoji: off/idle gray with strike-through, heating orange with flames, fault red, unknown gray. The value and card accent remain state-dependent (idle green, heating orange, fault red).
- Remove repeated simulator wording from metric cards; use concise metric-specific labels. The connection header retains an explicit Simulator / External badge and simulation control permission badges. Real equipment is never claimed to be controlled by the simulator.

## Scope
Frontend only; no API, simulator, DB, real device or TEST1 change. No git push.
