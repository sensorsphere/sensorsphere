# NET-UI-04 / NET-UI-05 — DEV

## NET-UI-04 (P1): Navigation and context
- Assets (card and table): Netatmo Heating action appears only for scoped Netatmo assets, opens the matching connection.
- Device Registry: action for devices with a NETATMO_MODULE_ID identity, derives connection from the identity, not from display names.
- History: searchable selector of Netatmo connections discovered from assets, opens Heating on selection.
- Dashboard Overview: direct entry to Netatmo Heating.
- Heating: selection follows the requested connection ID and keeps the selection while refreshing. Unknown/deleted connections show an explicit message rather than silently switching to another connection.
- User and Admin can navigate to Heating; connection configuration remains Admin-only.

## NET-UI-05 (P1): Multi-connection and real-device preparation
- Overview iterates all configured Netatmo connections; each connection has isolated device and metric queries.
- Metric matching uses the full home:module identity instead of only module ID; prevents collisions across homes with identical module IDs.
- Displays home and module identifiers, connection origin (approved simulator vs external), and explicit control capability.
- External/real connections are read-only even if the OAuth token advertises write_thermostat; SIM-02 is the only approved command endpoint. Other simulators are read-only by default.
- SIM-02 control disabled if discovery yields multiple thermostats because the current backend still uses a fixed simulator home/room. No ambiguous target may be controlled.
- No new OAuth scope requests, no real-device commands, no schema changes.

## Limitations / next step
- Physical Netatmo devices have not been connected or tested; external readiness is architectural, not a successful real-device validation.
- To enable real control later: persist explicit home/room targeting and device-specific capabilities, add role/authorization policy and explicit opt-in, validate commands and collected state on real hardware, then remove the SIM-02-only backend guard only under a separately approved scope.
- A multi-home connection is visible in supervision but control remains single approved simulator target.
- Browser-based acceptance of responsive layout and navigation still needed.
